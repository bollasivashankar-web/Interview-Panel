# Workflow QA and fixes — 19 October 2026

Story tested: company creates and publishes an interview, invites a candidate, candidate accepts and submits answers, and company views and evaluates the results.

## Issues fixed

1. **Candidate logo entered the company workspace.** The brand link targeted `/`, whose signed-in fallback opens `/company`. Candidate pages now link directly to `/candidate`. A browser regression verifies the destination.
2. **My interviews did not leave the device-check/interview screen.** Those screens are local state inside the same candidate route; navigating to the same route retained the state. Candidate components now remount on navigation entries, returning to the list. Saved answers and deadlines remain on the server and resume through the existing attempt endpoint. A browser regression verifies return from device check.
3. **API validation messages displayed as `[object Object]`.** FastAPI returns structured validation details, while the client passed that array directly into Error. A shared formatter now renders field names and messages, preserves ordinary server messages, and supplies a safe fallback for unexpected bodies. Unit tests cover malformed responses. A browser regression rejects an answer with HTTP 422, verifies readable feedback and retained answer text, then retries successfully.

## Scope and limits

Browser tests use headless Microsoft Edge with isolated identity/API fixtures. Backend tests use a temporary SQLite database, with external provider responses controlled by tests. Running local API/database readiness was checked separately. These checks are not a single live browser-to-production-provider transaction, nor a production PostgreSQL concurrency/load test.

Real email delivery, real AI grading requests, physical mobile devices, and production deployment were not exercised. No real candidate records were altered. Existing Vite large-chunk and Starlette TestClient deprecation warnings remain; neither prevented checks from passing. Docker CLI was unavailable on this shell's PATH, so container state was not independently confirmed in this run.
